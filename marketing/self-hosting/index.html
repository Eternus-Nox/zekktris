Self-hosting guide

Run your own Zekktris server

Zekktris runs on zekktris.com, and anyone can run their own server too: free, on a machine you control, set up with one command. This guide takes you from a bare machine to a running server, then through the apps, calls, updates and backups.

Linux + DockerAny distribution, with Docker Compose v2
2 GB memoryThe practical minimum
5 GB free diskPlus room for uploads
Free softwareGNU AGPL-3.0, nothing for sale

Quick start

On a Linux machine with Docker, run these three lines and answer the installer's questions.

Terminal
git clone https://github.com/Eternus-Nox/zekktris.git
cd zekktris
./install.sh

The public repository opens soon. Until then, this link only works for people who've been given access.

01 · Overview

What you get

Your server is its own place. Accounts, servers, messages and uploads live on your machine. An account on zekktris.com doesn't carry over, so everyone signs up on yours. The iPhone and Android apps can switch to your server from their sign-in screens (the desktop app from its next update), and the web app is served straight from it.

The installer sets up one Docker Compose stack of five containers:

ContainerWhat it does
zekktris-proxyCaddy 2.11.4. Serves the web app, gets HTTPS certificates by itself, and routes the API, the live connection and call setup.
zekktris-apiThe Zekktris server (Node.js 20), with the API and the realtime gateway. It applies database updates by itself when it starts, and runs as an unprivileged user.
zekktris-dbPostgreSQL 16, which holds every account, message and server.
zekktris-cacheRedis 7, for short-lived state only. Nothing in it needs backing up.
zekktris-livekitLiveKit 1.9.12, your own voice and video server. It's bundled and on by default.

Everything worth keeping is in one data folder (data/ inside the zekktris folder, or /mnt/user/appdata/zekktris on Unraid), plus the .env settings file the installer writes. The containers restart by themselves, so the server comes back after a reboot once Docker is running.

Zekktris is free software under the GNU AGPL-3.0 licence, so you can run it, change it and share it.

02 · Before you start

What you need

  • A machine that stays switched on, running Linux (any distribution): a spare PC, a Raspberry Pi 4 or 5, a NAS such as Unraid, or a small VPS.
  • macOS and Windows (through WSL) are fine for trying it out. Voice and video need Docker's host networking, which only fully works on Linux, so on those systems chat works for everyone but calls may only work on that machine.
  • Memory: 2 GB is the practical minimum. The installer warns you if there's less.
  • Disk: keep at least 5 GB free. Building the images needs about 3 GB, and the health check flags anything under 5 GB. On top of that, leave room for uploads (each file can be up to 100 MB by default).
  • Docker with the Docker Compose v2 plugin (the docker compose command), which the backup and update scripts rely on. On Linux (not Unraid) the installer can install Docker for you, but only if you say yes. On macOS use Docker Desktop or colima; on Unraid, turn Docker on in Settings.
  • git, curl, openssl and awk. These are usually already there.
  • For people outside your home: a public IPv4 address where you can forward ports on the router (a VPS already has one), and optionally a domain name. A home-network-only server needs neither.

Check Docker with:

Terminal
docker --version && docker compose version

03 · Decide

Choose how people reach your server

The installer offers three ways. Choose one with a flag, or answer its question with 1, 2 or 3. You can switch later.

OPTION 1

Just your public IP

./install.sh --ip
Your address
Looks like https://203.0.113.5. You don't need a domain, and HTTPS is still free and automatic: Caddy gets a Let's Encrypt certificate for the IP address itself. These certificates last 6 days, and Caddy renews them every couple of days.
You need
A real public IPv4 address. At home, the web and call ports must be forwarded to the server (the installer does it for you if the router supports UPnP).
Good for
A public IP or a VPS, without a domain. It's the installer's default when it finds a public IP.
Worth knowing
If your internet provider changes your IP, your server's address changes too. Run ./install.sh --reconfigure --ip, and everyone re-enters the new address. A free dynamic-DNS name (for example from duckdns.org) used with the domain option avoids this. Passkeys can't work on a bare IP address, so they're hidden.
OPTION 2

A domain name

./install.sh --domain chat.example.com
Your address
https://chat.example.com, with an ordinary Let's Encrypt certificate.
You need
A DNS "A" record that points the name at your public IP. The installer checks it and warns you if it points somewhere else. The ports are the same as for the IP option.
Good for
An address that never changes for your users, and passkeys in the browser.
Worth knowing
If the name is proxied by Cloudflare (orange cloud), switch it to "DNS only" for the first setup (see Behind Cloudflare or another proxy).
OPTION 3

Home network only

./install.sh --lan
Your address
http://<this machine's LAN address>:5550, for example http://192.168.1.20:5550. Nobody outside your network can connect, and the router isn't touched.
You need
Nothing extra.
Good for
Trying Zekktris out, or a household server. It's the installer's default when it can't find a public IP or finds carrier-grade NAT.
Worth knowing
The apps work fully there, calls included. A web browser can chat, but browsers only allow calls, push notifications and passkeys over HTTPS, so use the apps for calls.

Ports

Never forward port 7880: it's the voice server's internal port (see Voice and video calls).

Carrier-grade NAT. Some internet providers share one public IP between many customers. Then port forwarding can't reach your machine from outside, and the installer tells you so. Your options are to ask your provider for a public IPv4 address (often free or cheap), use a VPS, or run a home-network install meanwhile.

The installer also mentions Cloudflare Tunnel and Tailscale. A Cloudflare Tunnel can carry the website and chat, but not call audio and video.

You can switch later. ./install.sh --reconfigure asks again, or pass the new option, such as ./install.sh --domain chat.example.com. Your secrets and data are kept, and people re-enter the new address in their apps.

04 · Install

Install it

  1. Get the code onto the server

    Terminal
    git clone https://github.com/Eternus-Nox/zekktris.git
cd zekktris

    The public repository opens soon. Until then, this link only works for people who've been given access.

    Keep this folder. It's a git checkout, and the update script updates it in place later. Every command in this guide runs from it.

  2. Run the installer

    Terminal
    ./install.sh

    Or choose how people reach it up front, with one of these:

    • Just your public IP: ./install.sh --ip
    • A domain name: ./install.sh --domain chat.example.com
    • Home network only: ./install.sh --lan

    Run it as yourself or as root. If your user can only use Docker through sudo, the installer uses sudo for Docker by itself. Later on:

    • run the docker compose commands in this guide with sudo too, or join the docker group first (sudo usermod -aG docker $(whoami), then log out and back in);
    • run the scripts in scripts/ (update.sh, backup.sh, restore.sh and doctor.sh) with sudo even if you're in the docker group. The maintenance agent behind the Admin panel's buttons runs them as root, and the backups it takes can only be read by root. If you're root already, as on Unraid or many VPSs, leave out sudo.

  3. Answer its questions

    You only see the ones that apply to you:

    • On macOS or WSL: "Continue anyway?", because calls may only work on that machine.
    • If Docker is missing on Linux: "Download get.docker.com and run it as root now?" The default is No. Say yes, or install Docker from your distribution's packages and run the installer again.
    • "How should people reach your server?" 1, 2 or 3. Skipped if you passed --ip, --domain or --lan.
    • The domain name, or your public IP or LAN address if it couldn't work them out.
    • If another program already uses the ports (often nginx or Apache): "Continue anyway?" The default is No; stop that program first.
    • "Admin email:", then the admin password: at least 8 characters, typed twice, hidden.
    • "Where should the database and uploads live?" The default is data/ in the zekktris folder (/mnt/user/appdata/zekktris on Unraid).
    • If ufw or firewalld is running: "Open the Zekktris ports in ufw?" (or firewalld).
    • If your router supports UPnP: "Ask the router to forward the ports to this machine (UPnP)?" If it doesn't, the installer lists the ports to forward by hand and waits for you to press Enter. Tip: also give the server a fixed ("reserved") address in the router's DHCP settings.

  4. Let it finish

    The first build takes several minutes. Then the installer starts the server, waits for its startup checks, creates your admin account and, for the IP and domain options, waits up to 4 minutes for the HTTPS certificate.

    If the certificate isn't there yet, it shows what Caddy reported. Usually ports 80 and 443 aren't forwarded yet, or the provider blocks incoming port 80. Fix that, and Caddy picks it up by itself within a few minutes.

  5. Open your server

    At the end the installer prints your address, how to sign in, what to type in the apps, and the commands for updates, health checks and logs. Open the address and sign in with the admin email and password you chose.

Installing without questions

For scripts and automation:

Terminal
./install.sh --yes --domain chat.example.com --admin-email you@example.com --admin-password-file ~/zekktris-admin-password

With --yes, or without a terminal, you must pass --admin-email, and the password comes from the first line of --admin-password-file or from the ZEKKTRIS_ADMIN_PASSWORD environment variable. It's never passed as a command-line argument. --yes takes the recommended answer everywhere, except that it never runs Docker's install script, and it stops if the ports are taken. Delete the password file afterwards.

All the options

./install.sh --help lists them too.

Running it again is safe. With an existing .env it keeps your settings, only fills in what's missing, saves a copy of the old .env next to it, then rebuilds and restarts. Your secrets and data are never replaced. (./scripts/setup.sh still works too; it just runs the installer.)

05 · No surprises

What the installer changes

So you know exactly what it did:

  • .env in the zekktris folder, readable only by you. On a first install it's copied from .env.example and given fresh random secrets: DB_PASSWORD, JWT_SECRET, JWT_REFRESH_SECRET and FIELD_ENCRYPTION_KEY. It also sets APPDATA_PATH (your data folder), ACME_EMAIL (your admin email) and ALLOW_REGISTRATION=open.
  • Filled in only when they're empty: a voice key pair made just for your server (LIVEKIT_API_KEY and LIVEKIT_API_SECRET), LIVEKIT_IMAGE_TAG=v1.9.12, and the browser-notification keys (VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY and VAPID_CONTACT_EMAIL).
  • The address settings for the option you chose (in the table below).
  • The data folder, with db, uploads, caddy-data, caddy-config, desktop-updates, backups and control inside, plus a secrets folder in the zekktris folder.
  • Only if you agree: Docker itself, rules in ufw or firewalld, and port forwards on your router over UPnP (labelled "Zekktris").
  • Two images built from source on your machine (zekktris-api and zekktris-proxy; there are no prebuilt images), and the five containers.
  • Your admin account.
  • When you run it again: a copy of the previous .env, named .env.bak.<date-time>.

06 · Run it

Your admin account

You don't register the admin. Once the server is healthy, the installer creates that account itself, already verified and already an admin, with the email and password you gave it. Open your server's address and sign in.

Registration is already open while the installer runs, so it only ever creates a brand-new account. If someone registered your admin email first, the install stops instead of making them admin.

The Admin panel

In the web app, click the shield icon in the left rail, or go to /admin on your address. Admins see Overview, Users, Servers, Storage, Security, Perks and Backup & Maintenance.

  • Staff: open an account from Admin → Users to make it an Administrator or a Moderator. Moderators only see Users, Servers and Security.
  • Perk tiers: everything in Zekktris is free, cosmetics included. Scout, Guardian and Legend are tiers you give people, from Admin → Users → open an account → Perk tier, for 1, 3 or 6 months, or forever. They raise streaming quality:
TierScreen sharingCamera
EveryoneUp to 720p at 30 fpsUp to 1080p
ScoutUp to 1080p at 60 fpsUp to 1080p
GuardianUp to 2K at 60 fpsUp to 2K
LegendUp to 4K at 60 fpsUp to 4K

Those are the defaults. Change what each tier adds, and optional per-tier upload limits, in Admin → Perks.

No admin account?

To make an existing account an admin, or to create one by hand, run this on the server. It doesn't restart anything:

Terminal
docker compose exec -w /app/apps/api api node --import tsx/esm scripts/create-admin.ts --email you@example.com

It asks for a password twice (hidden). If that email already has an account with a verified address, it's made admin and its password is left alone, so just press Enter.

./install.sh --admin-email you@example.com does the same, and a plain ./install.sh re-run asks for an admin while the server has none. Both run the whole installer again, though, which rebuilds the images and restarts anything that changed.

To only check whether the server has an admin:

Terminal
docker compose exec -w /app/apps/api api node --import tsx/esm scripts/create-admin.ts --check

07 · Access

Who can sign up

ALLOW_REGISTRATION in .env decides who can make an account:

  • open: anyone who can reach your server can sign up. This is what the installer sets.
  • invite-only: signing up needs a sign-up code.
  • closed: nobody can sign up.

To change it, edit .env and apply it:

Terminal
docker compose up -d

The iPhone and Android apps read this before anyone signs in: on a closed server they say "This server isn't taking new sign-ups". On an invite-only server, people type their code into the sign-up form.

Creating sign-up codes

There's no admin screen for sign-up codes yet. You can create one in the database (this one works 5 times):

Terminal
docker compose exec db psql -U commune -d commune -c "INSERT INTO signup_codes (code, max_uses) VALUES ('pick-a-long-random-code', 5);"

Then share https://chat.example.com/register?code=pick-a-long-random-code (with your own address). The sign-up page fills the code in.

A simple private server. On a closed server the only new accounts are admins made with the create-admin command. So leave it open until your people have joined, then switch to closed.

08 · Your people

Connect the apps

Every app starts on zekktris.com. Get them here:

  • iPhone and iPad: the TestFlight beta (opens in a new tab)
  • Android: Zekktris.apk (Android 8 or later)
  • Desktop: Windows, macOS and Linux

Then point the app at your server. On iPhone and Android the switch is on the sign-in screens, so sign out first; an account belongs to the server that made it.

  • iPhone and iPad: on the sign-in or sign-up screen, tap Server: zekktris.com · Change, type your address and tap Connect. For a home-network server, allow it when iOS asks to find devices on your local network (or turn Zekktris on under Settings → Privacy & Security → Local Network), then tap Connect again. Widgets, Siri, the share sheet and the Apple Watch app all follow the server the iPhone app uses.
  • Android: on the welcome screen, tap Server: zekktris.com · Change, type the address and tap Connect.
  • Desktop: use the tray icon's Change server…, or Server: … · Change at the bottom of the sign-in page. Type the address and click Connect. Zekktris restarts on the new server, and you sign in there. The desktop app keeps updating itself from zekktris.com either way.
  • Web: just open your address in a browser.

Don't see the Server row? Update the app first; the switch needs a recent version. The desktop app gets it in its next update. Until then, open your server's address in a web browser.

What to type

Your installType this
Domainchat.example.com
IP203.0.113.5
Home network192.168.1.20:5550 (or http://192.168.1.20:5550)

If you leave out http:// or https://, the apps try HTTPS first. For a home-network address they then try plain http, on the port you typed, or on ports 80 and 5550 if you typed none. Plain http:// is only accepted for home-network addresses (10.x.x.x, 172.16.x.x to 172.31.x.x, 192.168.x.x, localhost and .local names); anything on the internet has to use HTTPS.

Before switching, each app checks that the address really answers as a Zekktris server, so a typo can't leave it pointing at nothing. Go back to zekktris.com, in the same place, switches back.

Signing in

Passwords and two-factor codes work on every server. The iPhone and Android apps only offer passkey sign-in on zekktris.com. On your own server, passkeys work in a web browser when the server has a domain name.

09 · Voice & video

Voice and video calls

Calls run on your own server: the bundled zekktris-livekit container, using a key pair the installer made just for your server. No outside account is needed.

How a call connects

  • Call setup goes through your normal address (at /livekit, on the same HTTPS certificate), so it needs no extra port.
  • The audio and video themselves go straight to the server on two ports: UDP 7882, the main media port, and TCP 7881, a fallback for networks that block UDP.
  • People on the same network as the server reach it directly. Everyone else needs both ports forwarded on your router to the server, and allowed in every firewall on the way, including a VPS provider's firewall panel, which the installer can't see. The installer opens them in ufw or firewalld and on the router (UPnP) when you let it, or lists them for you.

Never forward port 7880. It's the voice server's internal port. On a normal Linux install it only listens on the machine itself and on Docker's internal bridge.

If calls don't work

  • People can join a voice channel, but nobody outside your network hears or sees anything, and the call keeps reconnecting (LiveKit reports "negotiation timed out"): UDP 7882 and TCP 7881 aren't reachable. Forward and open them.
  • Calls stopped working for outside people after your public IP changed: the voice server only looks up its public address when it starts. sudo ./scripts/doctor.sh spots this, and sudo ./scripts/doctor.sh --fix restarts the voice server and installs a watchdog that checks every 5 minutes and restarts it after a change. A restart drops every call in progress, including ones on your home network that were still working.
  • The web and desktop apps say "Voice isn't set up on this server yet" (the iPhone app says "presence only — voice isn't configured on the server", and Android "Voice not available"): the voice keys are missing from .env (for example a hand-written one). Run ./install.sh again; it fills in a fresh pair and restarts. Setting only one of LIVEKIT_API_KEY and LIVEKIT_API_SECRET stops the server at its startup checks.
  • In a web browser on a home-network (http) server: browsers only allow the microphone and camera over HTTPS. Use the apps there. The desktop app treats your home-network server as secure, so calls work in it.

Good to know: no relay (TURN) server is bundled, so someone on a network that blocks both UDP 7882 and TCP 7881 can't get call audio or video. And calls show your server's public IP to the people in them, even if the website sits behind Cloudflare.

Prefer LiveKit Cloud?

Set these in .env, then run docker compose up -d. The bundled voice server then goes unused.

.env
LIVEKIT_WS_URL=wss://<project>.livekit.cloud
LIVEKIT_API_KEY=<that project's key>
LIVEKIT_API_SECRET=<that project's secret>
LIVEKIT_HTTP_URL=https://<project>.livekit.cloud

10 · Optional

Email: password resets and verification

Email is optional. Without it everything works except what needs a message in someone's inbox:

  • New accounts count as verified straight away.
  • "Forgot password" says: "Password reset is not available — this server has no email configured. Contact your server operator."
  • People can't change their account's email address, and admins can't send someone a reset link.
  • A teen linking a parent or guardian can only choose someone who already has an account on your server; there's no email invitation.

To turn it on, add an SMTP relay to .env. Any provider works, for example Resend, Brevo, SendGrid or Mailgun:

.env
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_USER=resend
SMTP_PASS=your-api-key
SMTP_FROM=noreply@your-domain.com
SMTP_SECURE=false

Then apply it:

Terminal
docker compose up -d
  • SMTP_FROM must be a plain email address. A display name such as Zekktris <noreply@your-domain.com> stops the server from starting. Use an address on a domain your provider has verified.
  • Use SMTP_SECURE=true for port 465; leave it false for 587.
  • Cloudflare Email Routing can't send mail. You need a real sending service.

Once email is on, new sign-ups get a verification link and have to confirm their address. Accounts created while email was off were already marked verified.

11 · Alerts

Notifications

  • In a web browser: notifications work on your server. The installer generated its web-push keys (VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY). Never change them once people have turned notifications on, because that breaks every existing subscription. Browsers only offer push over HTTPS, so this needs the IP or domain option.
  • In the desktop app: notifications pop up while the app is running, on any server.
  • In the official iPhone and Android apps: lock-screen push notifications only come from servers that hold the official apps' push keys (Apple's for iOS, the app's Firebase project for Android). A self-hosted server can't have those, so phones don't get push notifications from your server, and an iPhone won't ring for a call while the app is closed. Everything else in the apps works, and the apps' server picker says the same.

.env also has APNS_* settings for Apple, and you can add FCM_PROJECT_ID, FCM_CLIENT_EMAIL and FCM_PRIVATE_KEY for Firebase. They only help if you build and sign your own copies of the apps with your own Apple and Firebase accounts.

12 · Keep it current

Updating

See what an update would bring, with database changes called out. This touches nothing:

Terminal
sudo ./scripts/update.sh --check

Then update:

Terminal
sudo ./scripts/update.sh

A real update:

  1. fetches the latest code from the repository's master branch and lists the new commits;
  2. stops first if a file you edited locally is also changed by the update, and tells you which;
  3. takes a backup of the database and settings (--no-backup skips it; don't);
  4. rebuilds, restarts the server and waits for its startup checks;
  5. if the new version doesn't come up healthy, puts the previous code back and restarts it by itself.

Database updates apply themselves when the new server starts, and rolling the code back doesn't undo them. That's what the backup is for. An update that stopped halfway is picked up again by the next run.

Admins can do the same from Admin → Backup & Maintenance → Update & restart, once the maintenance agent is installed (see Health check and the maintenance agent; if you cloned the code as your normal user, do the one-time git step there too).

Changed something in .env? Apply it with docker compose up -d. (docker compose restart doesn't re-read .env.)

Updates come from github.com/Eternus-Nox/zekktris; until the public repository opens, fetching them needs access too. If update.sh can't reach it, it says so and just rebuilds the code you already have.

13 · Be safe

Backups and restore

A full backup:

Terminal
sudo ./scripts/backup.sh

A quick one, without attachments:

Terminal
sudo ./scripts/backup.sh --no-uploads

And a check that the newest one would restore:

Terminal
sudo ./scripts/restore.sh --check

Use sudo for these even if you're in the docker group: backups taken from the Admin panel or on a schedule belong to root, and nobody else can open them. (Leave it out if you're root already.)

  • backup.sh writes one bundle with everything needed to rebuild the server: a database dump, the uploads, .env (including the encryption key some database fields need) and the secrets folder.
  • --no-uploads leaves out attachments. It takes seconds instead of minutes, but on its own it can't bring back images and files.
  • Bundles go to the backups folder inside your data folder, named zekktris-<date>-<time>.tar.gz and readable only by the user who took them (root, with sudo or from the Admin panel). backup.sh keeps the newest 7 (change that with, for example, --keep 14). Every update also adds a database-only bundle, so copy your full bundles somewhere else.
  • restore.sh --check opens the newest bundle (or the one you name) and checks that the database dump inside is intact. A backup you've never checked is a hope, not a backup.
  • Copy bundles off the machine, and treat each one like the server itself: it holds every message, account and secret.

Automatic backups

Admin → Backup & Maintenance has buttons for a database backup, a full backup and verifying the newest one, plus a switch for automatic backups: every night at 03:30 a database-only one, and every Sunday at 04:00 a full one. They need the maintenance agent (see Health check and the maintenance agent). The Export server configuration button on that page only exports settings (no users or messages); it isn't a backup.

Restoring

Into an empty server (it refuses one that already has accounts):

Terminal
sudo ./scripts/restore.sh /path/to/zekktris-20261113-033000.tar.gz

Over whatever is there:

Terminal · replaces data
sudo ./scripts/restore.sh --force /path/to/zekktris-20261113-033000.tar.gz

--force replaces the whole database, so every message and account since that bundle is gone. A --no-uploads bundle only belongs on a server whose uploads folder is still there.

Moving to a new machine

  1. Install Zekktris there with ./install.sh.
  2. Copy the bundle over.
  3. Run sudo ./scripts/restore.sh --force with it (--force because the fresh install already has your admin account).

The restore brings back the old .env, keeping only the new machine's data-folder path, so the server keeps its old address settings. If the new machine is reached differently, run ./install.sh --reconfigure afterwards.

14 · Keep it healthy

Health check and the maintenance agent

Check the server (this only reports):

Terminal
sudo ./scripts/doctor.sh

Repair what's safe to repair:

Terminal
sudo ./scripts/doctor.sh --fix

If you're root, as on Unraid or many VPSs, leave out sudo. Otherwise keep it, even for the check: it looks at root's scheduled jobs and opens root's backups.

If you cloned the code as your normal user, also run this once, from the zekktris folder:

Terminal
sudo git config --system --add safe.directory "$(pwd)"

The maintenance agent runs as root from its schedule, and git refuses to work in a folder that belongs to another user, so without this the Admin panel's Update & restart fails. sudo ./scripts/doctor.sh --fix can't spot it, because under sudo git still trusts your own folder. The Check & repair setup button in Admin → Backup & Maintenance can: the agent runs it as root, and it fixes this too.

doctor.sh on its own checks Docker Compose and git, free disk space (it flags under 5 GB), the data folders, the scheduled jobs, that the api, db, cache and proxy containers are running and the API answers, that visitor addresses look right behind Cloudflare, whether the voice server advertises your current public IP, and that a recent, readable backup exists. It exits with an error while anything is wrong, so it also works from cron.

On a brand-new server it reports four problems until you run --fix once: a missing control/status folder in the data folder (the agent makes it on its first run), no maintenance agent, no voice-address watchdog, and no backups.

--fix creates missing folders, schedules the maintenance agent (every minute) and the voice-address watchdog (every 5 minutes), restarts the voice server if its public address is out of date, takes a first database backup if there are none, and, when it runs as root without sudo, fixes git's "dubious ownership" refusal. It never rebuilds or restarts the whole stack; that's the update script's job.

Run --fix with sudo: the maintenance agent is meant to run from root's schedule, and it writes its logs to /var/log. The agent is what carries out the Admin → Backup & Maintenance buttons. The API only drops a small request naming one of a fixed list of actions, so it never gets control of Docker. The agent needs a Linux host.

On Unraid, a reboot can drop these scheduled jobs. Run ./scripts/doctor.sh --fix again after a reboot, then turn Automatic backups back on in Admin → Backup & Maintenance (of the scheduled jobs, doctor.sh only puts back the agent and the watchdog).

15 · Advanced

Behind Cloudflare or another proxy

By default Caddy is the front door (EDGE_PROXY=none). It takes each visitor's address from the connection itself, and no request header can change it. Rate limits, bans and the sessions list rely on that.

Cloudflare's proxy (orange cloud) in front of a domain install

  • For the first install, set the DNS record to "DNS only", so Let's Encrypt can reach your server and the installer's DNS check passes.
  • To turn the orange cloud back on afterwards, set Cloudflare's SSL mode to "Full (strict)", add EDGE_PROXY=cloudflare to .env, and run docker compose up -d proxy.
  • Turn off Cloudflare features that add scripts to pages (Rocket Loader, Zaraz, automatic Web Analytics, JavaScript bot detections). The app only lets its own scripts run, and Rocket Loader can leave a blank page.

Cloudflare Tunnel, or your own nginx or Traefik handling HTTPS

Caddy then serves plain HTTP on port 5550, and PUBLIC_URL is the public https address. The installer has no tunnel option, so the simplest route is ./install.sh --lan, then set these in .env:

.env
PUBLIC_URL=https://chat.example.com
COOKIE_SECURE=true
SITE_ADDRESS=:5550
HTTP_PORT=5550
HTTPS_PORT=5551
TLS_MODE=none
EDGE_PROXY=cloudflare
LIVEKIT_USE_EXTERNAL_IP=true
LIVEKIT_HOST=

Use EDGE_PROXY=cloudflare only for Cloudflare; leave it at none for nginx or Traefik. For calls from outside, forward UDP 7882 and TCP 7881 to the server. Then apply it with docker compose up -d.

  • Run the Cloudflare Tunnel connector (cloudflared) on the server itself: directly on the machine, pointed at http://localhost:5550, or in a Docker container on it, pointed at http://<the server's LAN address>:5550. With EDGE_PROXY=cloudflare, Caddy only trusts Cloudflare's own addresses and Docker's internal network, so a connector on another machine makes every visitor look like that machine.
  • Point nginx or Traefik at http://localhost:5550 on the same machine, or http://<the server's LAN address>:5550 from another one. Never use a container's own IP; it changes whenever the container is recreated. The tunnel or proxy must pass WebSocket connections through (the app uses /gateway and /livekit).
  • On a VPS, Docker opens port 5550 to the internet even with ufw on, so anyone can still reach the server over plain http, around Cloudflare or your proxy. Block TCP 5550 in your provider's firewall panel, or allow only your proxy's address there. A tunnel or proxy on the same machine doesn't go through that firewall, so it keeps working.
  • Don't run ./install.sh --reconfigure or ./install.sh --domain on this server afterwards: they rewrite the address settings, and the tunnel stops reaching it. A plain ./install.sh re-run keeps your address settings.
  • Only set EDGE_PROXY=cloudflare when every outside request comes through Cloudflare. Anywhere else, visitors could choose their own address. ./scripts/doctor.sh and ./scripts/update.sh warn you if they see tunnel traffic without it.
  • EDGE_PROXY only accepts none or cloudflare. Behind nginx, Traefik or similar, every visitor looks like the proxy's address to rate limits, bans and the sessions list.

Calls never pass through Cloudflare. The voice server has to be reachable on your public IP (UDP 7882 and TCP 7881). So behind carrier-grade NAT, a tunnel makes chat reachable from anywhere, but calls only work on your own network.

16 · When things go wrong

Troubleshooting

Find the symptom, open it, and do what it says.

Installing

The installer says "Docker is installed but not usable by …"

Start Docker, or add yourself to the docker group, then log out and back in:

Terminal
sudo usermod -aG docker $(whoami)
The installer says ports are "Already in use by another program"

Another web server (often nginx or Apache) holds them. Stop it, or keep it and put Zekktris behind it (see Behind Cloudflare or another proxy).

The installer says "No certificate yet"

Forward TCP 80 and 443 to the server (and open them in a VPS provider's firewall), check that your domain's A record points at your public IP, and know that some providers block incoming port 80. Caddy keeps retrying by itself; see what it says with docker compose logs proxy.

The installer warns about carrier-grade NAT

Port forwarding can't reach you. Ask your provider for a public IPv4 address, use a VPS, or keep a home-network install.

Signing in and connecting

You sign in and are signed straight back out

COOKIE_SECURE has to match PUBLIC_URL: true for https://, false for http://. Fix .env, then run docker compose up -d.

An app says "Something answered at that address, but it isn't a Zekktris server."

The address reaches something else: your router's page, another web server, the wrong port, or a proxy that doesn't pass /api through. This should print JSON containing "software":"zekktris" (use your own address):

Terminal
curl -s https://chat.example.com/api/v1/instance/info
An app says "That server's HTTPS certificate isn't valid."

The certificate hasn't been issued yet; see "No certificate yet" above.

An app refuses plain http://

Use https:// for anything on the internet. Plain http:// only works for home-network addresses.

An app says "Couldn't reach that server."

Check the address and port, that the server is running (docker compose ps), and that the ports are forwarded. On iPhone, for a home-network server, allow Local Network access for Zekktris.

Everyone shows the same IP in the sessions list, or one person's rate limit hits everyone

You're behind Cloudflare without EDGE_PROXY=cloudflare. Add it to .env, then run docker compose up -d proxy.

A blank page behind Cloudflare

Turn off Rocket Loader and other script-adding features, then reload.

Calls

People join a call, but nobody outside your network hears or sees anything

UDP 7882 and TCP 7881 aren't reachable from outside. Forward and open them. If your public IP changed recently, run sudo ./scripts/doctor.sh --fix.

"Voice isn't set up on this server yet", "presence only" or "Voice not available"

That's how the web and desktop apps, the iPhone app and the Android app say the voice keys are missing from .env. Run ./install.sh again.

Calls don't work in a web browser on a home-network server

Browsers need HTTPS for the microphone and camera. Use the apps, or move to the IP or domain option.

Running the server

"Password reset is not available — this server has no email configured"

Set up email (see Email).

The server won't start, or keeps restarting

docker compose logs api shows its startup checks and which one failed. Usually it's a bad .env value: SMTP_FROM with a display name, JWT_SECRET equal to JWT_REFRESH_SECRET, or only one of the two voice keys set.

Port forwards disappeared after a router restart

A plain ./install.sh re-run doesn't touch the router. Run it with your option again (./install.sh --ip, or ./install.sh --domain chat.example.com), or use ./install.sh --reconfigure.

Your provider changed your public IP (IP option)

Run ./install.sh --reconfigure --ip, and everyone re-enters the new address.

update.sh or doctor.sh says git refuses the directory ("dubious ownership")

Git won't work in a folder that belongs to another user, and the maintenance agent behind the Admin panel's buttons runs as root. Fix it once, from the zekktris folder:

Terminal
sudo git config --system --add safe.directory "$(pwd)"

As root without sudo (as on Unraid), ./scripts/doctor.sh --fix does this for you, and so does Check & repair setup in Admin → Backup & Maintenance. sudo ./scripts/doctor.sh --fix doesn't: under sudo, git still trusts your own folder, so it never sees the problem.

Admin → Backup & Maintenance says "The maintenance agent isn't running"

Run sudo ./scripts/doctor.sh --fix on the server. (The cron line the panel shows uses a path from inside the container; doctor.sh installs the right one.)

After an update or a restore, docker compose up -d stops with "container zekktris-api is unhealthy"

The server is still handing its uploads folder over to its own user (a one-time step on older installs). Wait until docker compose logs api shows "api-entrypoint: handed" and docker compose ps shows the api as healthy, then run docker compose up -d again.

You changed .env and nothing happened

Apply it with docker compose up -d. docker compose restart doesn't re-read .env.

17 · Security

Security notes

  • .env holds every secret: the database password, the sign-in token keys, the field-encryption key, and the voice and push keys. It's readable only by you; never share it or commit it. The .env.bak.* and .env.before-restore-* copies hold the same secrets.
  • Backup bundles hold the whole database plus .env and the secrets folder, and are written readable only by the user who took them (root, with sudo or from the Admin panel). A copy of a bundle is a copy of your server, so store it safely.
  • FIELD_ENCRYPTION_KEY encrypts two-factor secrets and bot signing secrets in the database. Keep it stable: if it's lost, people have to set up two-factor again. It's in .env and in every bundle.
  • Registration starts open, so anyone who can reach your server can sign up. See Who can sign up.
  • Only forward the ports listed in this guide, and never 7880. Docker publishes the web ports past ufw and firewalld, so the host firewall doesn't hide them.
  • The Zekktris server process runs as an unprivileged user. It only falls back to root, and says so in its log, if it can't take over the uploads folder. The root-run maintenance agent only carries out a fixed list of actions; the API can only queue a request naming one, so it never gets control of Docker.
  • Visitor addresses are only taken from a proxy when you say one is in front (EDGE_PROXY=cloudflare), and only from Cloudflare.
  • Calls reveal your server's public IP to the people in them, even behind Cloudflare.
  • Two clean-up jobs are on by default, and they really delete things:
    • Accounts nobody has opened the app with for 365 days are deleted. Admins and server owners are skipped, and messages stay, shown as from a deleted user. Set INACTIVITY_TTL_DAYS=0 to turn this off.
    • The full-size copies of images older than 90 days are removed, and a small thumbnail stays in their place. Messages stay, pinned messages are skipped, and attachments without a thumbnail (videos, other files and voice notes) are kept. Set ATTACHMENT_RETENTION_DAYS=0 to keep everything, or ATTACHMENT_RETENTION_DRY_RUN=true to preview first.
    Apply changes with docker compose up -d.
  • Your server's Terms and Privacy pages show the default Zekktris terms, with a notice that the server is run independently by its own administrators, who are responsible for it and for their users' data.
  • Zekktris is licensed under the GNU AGPL-3.0. If you run a modified version for other people, set SOURCE_CODE_URL in .env to where your changed source can be downloaded; the web app links to it from the Terms and Privacy pages.
  • The installer only runs Docker's install script after you explicitly say yes, and never takes the admin password as a command-line argument.
  • Webhook tokens are masked in the proxy's logs.
  • What the scripts contact: your public IP is looked up through api.ipify.org (with ipv4.icanhazip.com and ifconfig.me as fallbacks or cross-checks), and the installer checks your domain's DNS through dns.google.

18 · Moving on

Uninstalling

Take a last backup first if you might want the data later (the server has to be running), and copy it somewhere safe:

Terminal
sudo ./scripts/backup.sh

To stop Zekktris and remove its containers, while keeping your data where it is:

Terminal
docker compose down

To remove everything, permanently, run this from the zekktris folder:

Terminal · deletes everything
docker compose down --rmi all
cd ..
sudo rm -rf zekktris

That deletes the zekktris folder, including the default data folder inside it (database, uploads, certificates and backups). sudo is needed because some of those files belong to the containers' users. If you chose another data folder (--data-dir, or /mnt/user/appdata/zekktris on Unraid), delete that too.

Then tidy up what lives outside the folder:

  • Scheduled jobs, if you ran doctor.sh --fix or turned on automatic backups: open root's schedule with sudo crontab -e and delete the lines ending in # zekktris-agent, # zekktris-livekit and # zekktris-backup. Their logs are /var/log/zk-agent.log, /var/log/zk-livekit.log and /var/log/zk-backup.log.
  • Router: remove the port forwards. The installer's UPnP ones are labelled "Zekktris".
  • Firewall: close the ports the installer opened. For example, with ufw:
Terminal · ufw
sudo ufw delete allow 7882/udp

Or with firewalld:

Terminal · firewalld
sudo firewall-cmd --permanent --remove-port=7882/udp
sudo firewall-cmd --reload

Repeat for each port: TCP 80, 443 and 7881 and UDP 443 and 7882 (for a home-network install: TCP 5550 and 7881, and UDP 7882).

19 · Questions

FAQ

Is it really free?

Yes. Zekktris is free software under the GNU AGPL-3.0, and nothing in it costs money: cosmetics are free on every account, and you give out the perk tiers for higher-quality streaming free of charge. You only pay for your own hardware or VPS, if you use one.

Does my zekktris.com account work on my server?

No. Each server stands on its own, so people sign up on yours. Servers aren't linked either: people on your server can't message people on zekktris.com, and Discovery lists only your server's communities.

Will phones get notifications from my server?

Not lock-screen push notifications in the official iPhone and Android apps: those only come from servers that hold the apps' push keys. Browsers get notifications over HTTPS, and the desktop app shows them while it's running. See Notifications.

Do passkeys work on my server?

In a web browser, on a server with a domain name. Not on a bare IP or a home-network address, and the iPhone and Android apps only offer passkeys on zekktris.com. Passwords and two-factor codes work everywhere. Passkeys are tied to your server's address, so after a move to a new domain people add them again.

Can I run it on a Raspberry Pi or a NAS?

Yes: any Linux machine that stays on, such as a Raspberry Pi 4 or 5 or an Unraid NAS, with Docker and at least 2 GB of memory. On Unraid the data folder defaults to /mnt/user/appdata/zekktris.

Can I try it on my Mac or Windows PC?

Yes, with Docker Desktop or colima on a Mac, or WSL on Windows. Chat works for everyone, but calls may only work on that machine, because voice and video need Docker's host networking, which only fully works on Linux. For a real server, use Linux.

Does anything get deleted automatically?

Two clean-up jobs are on by default: accounts nobody has opened the app with for 365 days are deleted (admins and server owners are skipped), and the full-size copies of images older than 90 days are removed, leaving a thumbnail (messages stay, pinned messages are skipped, and videos, other files and voice notes are kept). Set INACTIVITY_TTL_DAYS=0 or ATTACHMENT_RETENTION_DAYS=0 in .env to turn them off. See Security notes.

How do I give someone 4K screen sharing?

Admin → Users → open their account → Perk tier. Legend unlocks 4K by default (Guardian 2K, Scout 1080p at 60 fps). Perks are free, and you choose what each one unlocks in Admin → Perks.

Can I keep my server private?

Yes. Set ALLOW_REGISTRATION to invite-only or closed, or pick the home-network option so nobody outside can reach it. See Who can sign up.

Where's the source code?

Zekktris is licensed under the GNU AGPL-3.0, and its public repository, github.com/Eternus-Nox/zekktris, opens soon. If you run a modified version for other people, set SOURCE_CODE_URL in .env to where your changed source can be downloaded.
